# Contributing

Thanks for contributing to Maintainer Flow.

## Contribution areas

- request parsing quality
- repository matching heuristics
- validation adapter integrations
- output formatting
- docs and examples

## Local development

```bash
python -m auditor
```

## Contribution rules

1. Keep changes scoped.
2. Explain maintenance risk clearly.
3. Prefer deterministic output over broad generation.
4. Update docs when workflow changes.
5. Add example artifact when summary format changes.

## Pull request checklist

- code runs locally
- README still matches workflow
- examples reflect current output
- changelog updated for notable behavior changes
